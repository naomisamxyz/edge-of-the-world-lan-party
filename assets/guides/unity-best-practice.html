Project baseline

    
Set clear standards early and apply them consistently. A new project should match this before you build anything on it.


    

    

      

        
Every new project

        

          
Editor
Unity 2022.3 LTS with the Windows, Mac, and WebGL modules.

          
Pipeline
a URP project, with Input System and Cinemachine installed.

          
Settings
visible .meta files, text serialization, 1920×1080 at 16:9, a distinct Play Mode tint.

          
Workspace
the Lighting window docked and the Editor layout saved.

          
Smoke test
rendering, lighting, input, Cinemachine, physics, audio, and build settings all confirmed working.

        

      

    


    
Alternatively, duplicate a working project or template and rename it. Remove the hidden .git folder from the copy only, then initialize a new repository for it.

  


  

  

    
Storage and backups

    
A Unity project is thousands of small files. Keep it somewhere fast and back it up as a whole.


    

    

      

        
Where it lives

        

          
Good
an external SSD with plenty of free space.

          
Avoid
mechanical drives, cloud-synced folders, and USB sticks.

          
Always
close Unity before disconnecting a drive, and never let that drive hold the only copy.

        

      


      

        
Backing up

        

          
How
close Unity, compress the project folder, copy the ZIP somewhere else.

          
Skip
the generated Library, Temp, Logs, and Obj folders.

          
Name
sequentially and clearly, such as ProjectX_01.zip.

        

      

    

  


  

  

    
Version control

    
Use source control from the first day. Git records history locally; a remote like GitHub adds an off-machine backup and lets others work with you.


    

    

      

        
Set it up for Unity

        

          
Meta files
visible, with text-based asset serialization.

          
.gitignore
a Unity-specific one — GitHub and Unity .gitignore guidance.

          
Large binaries
consider Git LFS; never commit generated folders.

          
Alternative
Unity Version Control (formerly Plastic SCM) is built for code and large binary assets — set it up.

        

      

    


    
Commit and push regularly with short messages such as “Add player movement,” especially before experimental changes or installing a package. To recover from a ZIP backup, extract it to a new folder and open the copy. To recover with Git, find the last working commit and revert the unwanted changes.

  


  

  

    
Universal Render Pipeline

    
Check Project Settings → Graphics and Quality for an assigned URP Pipeline Asset. If URP is not configured, install Universal RP, create a pipeline asset with Create → Rendering → URP Pipeline Asset, and assign it in both places. Keep Pipeline and Renderer assets in a clearly named settings folder.


    

    

      

        
Working in URP

        

          
Shaders
use URP-compatible ones such as Universal Render Pipeline/Lit. Bright pink usually means an incompatible or missing shader.

          
Converting
use Window → Rendering → Render Pipeline Converter where appropriate, then check cameras, lights, shadows, post-processing Volumes, and quality settings.

          
Timing
do not switch pipelines late in production.

Assets and naming

    
Move assets inside Unity so their .meta files stay connected. Moving through the operating system means moving each asset and its .meta file together. Keep the root Assets folder clean and organize by type or by object / area.


    

      

        


Assets/Materials/Level1
Assets/Prefabs/Characters
Assets/Audio/Ambience

Assets/Forest/Trees/BigTree/BigTree.fbx
Assets/Forest/Trees/BigTree/BigTree.mat

Naming

        

          
Style
one consistent convention, such as PascalCase or camelCase.

          
Suffixes
meaningful ones like _N for normal maps, _AO for ambient occlusion.

          
Prototypes
kept separate; production assets should not depend on placeholders.

        

      

    


    
Avoid the Resources folder unless runtime loading needs it. Match asset quality to its on-screen use, set compression and platform settings, and treat one Unity unit as one meter for most physics-based 3D games.

  


  

  

    
Project architecture

    
Structure that keeps a project workable as it grows.


    

    

      

        
Building blocks

        

          
Assembly Definitions
split scripts into assemblies so Unity recompiles only affected areas. Use them for clear systems — gameplay, UI, tools, shared code — not for every small folder.

          
Prefabs
reusable GameObjects; instances inherit central updates while allowing overrides, and Prefab Variants share a base. Prefab editing mode.

          
ScriptableObjects
reusable shared data — items, characters, abilities, dialogue, difficulty, settings — not temporary gameplay state.

          
Scene hierarchies
keep them shallow. Group objects only when they genuinely move, rotate, scale, or activate together.

        

      

    

  


  

  

    
Testing and debugging

    
Add development cheats and checkpoints early — teleportation, progression skips, currency, item unlocks — so you are not repeating setup. Keep small scenes dedicated to individual features.


    

    

      

        
While developing

        

          
Console
open Window → General → Console and fix the first error first — one error often triggers several more.

          
Lighting
use real-time lights while iterating. When ready, mark stationary geometry for global illumination, set suitable lights to Baked or Mixed, then generate lighting. Reserve real-time lights and shadows for things that move or change.

Performance and builds
