Project Baseline
Establish clear standards early and apply them consistently. Use Unity 2022.3 LTS with the required Windows, Mac, and WebGL modules. Create a URP project, install Input System and Cinemachine, enable visible .meta files and text serialization, use 1920×1080 at 16:9, choose a distinct Play Mode tint, add the Lighting window, save the Editor layout, and test rendering, lighting, input, Cinemachine, physics, audio, and build settings.
Alternatively, duplicate a working project or template and rename it. Remove the hidden .git folder from the copy only, then initialize a new repository for the copied project.


Storage and Backups
If possible, keep projects on an external SSD with enough free space. Avoid mechanical drives, cloud-synced folders, and USB drives. Close Unity before disconnecting a drive, and never make that drive the project’s only copy.
To back up, close Unity, compress the project folder, and copy the ZIP elsewhere. Generated Library, Temp, Logs, and Obj folders can be omitted. Name sequential backups clearly, such as ProjectX_01.zip.


Version Control
Use source control from the beginning. Git records history locally; GitHub can provide a remote copy for backup and collaboration. Use visible .meta files, text-based asset serialization, and a Unity-specific .gitignore. Consider Git LFS for large binary assets. Do not commit generated folders.
GitHub and Unity .gitignore guidance
Unity Version Control, formerly Plastic SCM, is another option designed for code and large binary assets. Set up Unity Version Control.
Commit and push regularly with short descriptions such as “Add player movement,” especially before experimental changes or package installation. To recover a ZIP backup, extract it to a new folder and open that copy. To recover with Git, locate the last working commit and revert the unwanted changes.


Universal Render Pipeline
Check Project Settings → Graphics and Quality for an assigned URP Pipeline Asset. If URP is not configured, install Universal RP, create a pipeline asset with Create → Rendering → URP Pipeline Asset, and assign it in both locations. Keep Pipeline and Renderer assets in a clearly named settings folder.
Use URP-compatible shaders such as Universal Render Pipeline/Lit. Bright pink usually indicates an incompatible or missing shader. Use Window → Rendering → Render Pipeline Converter where appropriate. Check cameras, lights, shadows, post-processing Volumes, and quality settings after conversion. Avoid switching pipelines late in production.

Assets and Naming
Move assets inside Unity so their .meta files stay connected. If moving through the operating system, move each asset and its .meta file together. Keep the root Assets folder clean and organize either by asset type or by object/area.

Avoid the Resources folder unless runtime loading requires it. Match asset quality to its on-screen use, configure compression and platform settings, and treat one Unity unit as one meter for most physics-based 3D games.
Choose a consistent naming style such as PascalCase or camelCase. Use meaningful suffixes like _N for normal maps and _AO for ambient occlusion. Keep prototypes separate and avoid production assets depending on placeholders.


Project Architecture
Assembly Definitions
Assembly Definition files divide scripts into assemblies so Unity recompiles only affected areas. Use them for clear systems such as gameplay, UI, tools, and shared code—not for every small folder.
Prefabs
Use prefabs for reusable GameObjects. Instances inherit central updates while allowing selected overrides; Prefab Variants share a foundation. Prefab editing mode.
ScriptableObjects
Use ScriptableObjects for reusable shared data such as items, characters, abilities, dialogue, difficulty, and settings—not temporary gameplay state.
Scene Hierarchies
Keep hierarchies shallow. Group objects only when they genuinely need to move, rotate, scale, or activate together.


Testing and Debugging
Add development cheats and checkpoints early: teleportation, progression skips, currency, and item unlocks reduce repetitive setup. Maintain small scenes dedicated to individual features.
Open Window → General → Console. Fix the first error before later ones because one error may trigger several more.
Use real-time lights while developing. When ready, mark stationary geometry for global illumination, set suitable lights to Baked or Mixed, then generate lighting. Reserve real-time lights and shadows for objects that move or change.

Performance and Builds
Before building, remove unused scenes, compress textures and audio, bake lighting when appropriate, disable unnecessary shadows and effects, and choose quality settings for the target computer.
  1. Open File → Build Settings.
  2. For profiling, enable Development Build and Autoconnect Profiler.
  3. Select Build and Run.
  4. Open Window → Analysis → Profiler.
  5. Test the build while watching CPU, GPU, rendering, and memory.
For the final release, disable Development Build, Autoconnect Profiler, and Script Debugging. Export into a new empty folder and test outside the Editor. When sharing, ZIP the entire build folder.
