Chatbots

    
Chat models such as ChatGPT, Claude, and Gemini are useful as a patient tutor and a rubber duck: for explaining errors, unblocking syntax, and talking through a design before you build it.


    
What they are good at

    
    
      
  • Explaining a compiler error or a Unity console message in plain language.
    • 
      
  • Turning an idea (“I want the door to open when the player is near”) into a Unity approach you can then build.
    • 
      
  • Reviewing a short script you already wrote and pointing at likely problems.
    • 
      
  • Summarising documentation, or drafting boilerplate you intend to rewrite.
    • 
    


    
Asking well

    
Paste the whole error message and the relevant code, say what you expected versus what actually happened, and mention your Unity version. Vague questions get vague answers.


    
Where they break

    
    
      
  • They confidently invent methods, components, and menu paths that do not exist. Check every API name against the Unity Scripting Reference before trusting it.
    • 
      
  • They do not know your project. Anything about your scene, your file layout, or code they have not seen is a guess.
    • 
      
  • Long threads drift. Keep one chat per problem rather than one endless conversation.
    • 
    

  


  

  

    
Coding agents

    
Coding agents such as Claude Code, Cursor, and GitHub Copilot go a step further than a chatbot: they read the files in your project and can write changes directly into them.


    
What they are for

    
    
      
  • Scaffolding a new script from a clear description.
    • 
      
  • Making the same edit across several files.
    • 
      
  • Wiring up a system you can describe precisely.
    • 
      
  • Tracking a bug that crosses more than one file.
    • 
    


    
Staying in control

    
    
      
  • Work in small steps. Ask for one change, read the diff, run it in Unity, then continue. A 500-line change you did not watch happen is a change you do not understand.
    • 
      
  • Use version control (see Unity Best Practice). Commit before you let an agent work, so a bad run is one command to throw away.
    • 
      
  • Point it at Assets/Scripts, not the whole project. Keep generated folders and .meta files out of what it touches.
    • 
      
  • You are still the author. If you cannot explain what a script does and why, it is not finished, no matter who typed it.
    • 
    

  


  

  

    
Generating assets

    
Generative tools can produce 3D models, textures, sprites, sound, and music from a text prompt or an image. Treat the output as raw material, not finished work.


    
    
      
  • 3D models: Meshy, Tripo, and Rodin do text-to-mesh or image-to-mesh. Expect messy topology and lighting baked into the texture. Good for blockouts, background props, and anything you plan to retexture.
    • 
      
  • Textures, sprites, concept art: image generators, plus texture-specific tools. Watch for seams that do not tile and style that drifts across a set.
    • 
      
  • Audio: tools exist for sound effects and for music beds. Check the licence before you ship anything.
    • 
      
  • Animation: Mixamo for auto-rigging and a motion library (not generative), and video-to-mocap tools such as DeepMotion.
    • 
    


    
Getting it into Unity

    
Import models as FBX or glTF, keep one Unity unit as one metre, and move files inside Unity so their .meta links survive (see First Project Setup and Unity Best Practice).

  


  

  

    
Using them critically

    
This is an art course, and these tools are part of its subject, not only its toolkit.


    
These models are trained on scraped text, code, images, and audio — much of it copyrighted, most of it uncredited. The labour of filtering and rating their output is real and largely invisible, and running them carries a material energy and water cost.

    
That is not an argument against using them. It is an argument for using them deliberately: know what a tool is doing, whose work it is standing on, and what it is for in your piece. The constraints you set around a tool are part of the work.

    
If your project is about these systems, start from the course readings on games, automation, and ecology, and bring it to critique.
