Cinemachine

    
Cinemachine is Unity's camera system. Instead of scripting camera movement and math by hand, you place a virtual camera, tell it what to follow and what to look at, and it handles the smoothing, framing, and cuts for you. Use it for a camera that follows the player, cutscene shots, and switching between angles. It's worth using because a good camera is most of what makes a game feel controllable — Cinemachine gets you there without reinventing follow-and-look math every project.

  


  

  

    
Character controllers

    
Unity's official First Person and Third Person Character Controllers are ready-made player movement — walking, running, jumping, looking around, and, in third person, an orbiting camera — all wired up and already tuned. Use one as your player's starting point instead of writing movement and camera code from zero. It's worth using because it gets you moving around a scene in minutes, and gives you a working, testable reference to change once you know what you want different.

  


  

  

    
New Input System

    
The Input System is how Unity reads keyboard, mouse, gamepad, and touch input. The “new” one (as opposed to the old Input Manager) lets you define actions like Move or Jump once, then map them to any device. Use it for anything the player presses, moves, or aims. It's worth using because it separates what a control does from which physical button does it — supporting a gamepad later doesn't mean rewriting your scripts.


    
Setup

    
    
      
  1. Install the package
        
      
          
    • Window → Package Manager
      • 
          
    • Select Unity Registry
      • 
          
    • Find Input System
      • 
          
    • Click Install
      • 
        
    
      
    2. 
      
  2. Enable it
        
      
          
    • Unity may ask to enable the new Input System and restart — click Yes.
      • 
          
    • Or manually: Edit → Project Settings → Player → Other Settings → Active Input Handling, set to Input System Package (New).
      • 
        
    
      
    3. 
      
  3. Create an Input Actions asset
        
      
          
    • In the Project window: right-click → Create → Input Actions.
      • 
          
    • Name it something like PlayerControls.
      • 
        
    
      
    4. 
      
  4. Open the Input Actions asset
        
      
          
    • Double-click it.
      • 
          
    • Create an Action Map called Player.
      • 
        
    
      
    5. 
      
  5. Add actions
        
    
          
    
            
    
              
    Move
    Action Type Value, Control Type Vector2.
    
              
    Look
    Action Type Value, Control Type Vector2.
    
              
    Jump
    Action Type Button, Control Type Button.
    
              
    Interact
    Action Type Button, Control Type Button.
    
            
    
          
    
        
    
      
    6. 
      
  6. Add bindings for each action
        
      
          
    • Move — add a 2D Vector Composite:
            
        
              
      • Up W · Down S · Left A · Right D
        • 
              
      • Optional: add another binding for <Gamepad>/leftStick.
        • 
            
      
          
      • 
          
    • Look — <Mouse>/delta, <Gamepad>/rightStick.
      • 
          
    • Jump — <Keyboard>/space, <Gamepad>/buttonSouth.
      • 
          
    • Interact — <Keyboard>/e, plus a gamepad button of your choice.
      • 
        
    
      
    7. 
      
  7. Add Player Input to your player
        
      
          
    • Select your Player GameObject.
      • 
          
    • Add Component → Player Input.
      • 
          
    • Drag PlayerControls into Actions.
      • 
          
    • Set Default Map to Player.
      • 
        
    
      
    8. 
      
  8. Connect it to your movement script
        
    On the Player Input component, set Behavior to Send Messages — the simplest of the four options. In plain terms: “whenever an action happens, call a method with a matching name on this same object.”
    
        
      
          
    • The method name has to match the action name, with “On” in front: the action is called Move, so Unity looks for a method called OnMove. Rename the action to Sprint and you'd need OnSprint instead.
      • 
          
    • These methods have to live in a script on the same GameObject as the Player Input component — that's how Unity knows where to look for them.
      • 
          
    • Add using UnityEngine.InputSystem; at the top of that script, or InputValue below won't be recognized.
      • 
          
    • InputValue value is just a small box Unity hands you, holding whatever was pressed or moved. value.Get<Vector2>() opens the box — since Move's Control Type is Vector2, this gives you the direction the player is pushing, as an (x, y) pair. value.isPressed is the same idea for a button: just true or false.
      • 
        
    
        
    Put together, here's what Unity calls automatically as the player moves and jumps:
    
        
    public void OnMove(InputValue value)
{
    Vector2 movement = value.Get<Vector2>();
}

public void OnJump(InputValue value)
{
    if (value.isPressed)
    {
        // Jump
    }
}
