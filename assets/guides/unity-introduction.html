First script

    
A Unity script is a C# class that Unity runs on an object in the scene. This one reads the keyboard every frame and moves whatever object it is attached to. Make a file named MoveObject.cs and paste this in:


    


      

        

          
          
          
          
          
        

        


using UnityEngine;

public class MoveObject : MonoBehaviour
{
    public float speed = 3f;

    void Update()
    {
        float x = Input.GetAxis("Horizontal");

        float z = Input.GetAxis("Vertical");

        Vector3 movement = new Vector3(x, 0f, z);

        transform.Translate(movement * speed * Time.deltaTime);
    }
}

        

      


      


        

          IMPORT
          
Gives the script access to Unity's features — types such as MonoBehaviour, Vector3, Transform, Input, and Time. Almost every script starts with this line.

        


        

          THE CLASS
          
A class groups related data and instructions together. Everything from public class to the final } is its body. The name we chose is MoveObject, so the file must be named MoveObject.cs. : MonoBehaviour is what lets the class work as a Unity component — attached to a GameObject and able to use methods like Update().

        


        

          INSPECTOR FIELD
          
A variable is a named place to store a value. public makes it show up as an editable slot in the Inspector, so you can change it without editing code. float is a number that can have decimals. speed is the name. = 3f gives it a starting value of 3 — the f tells C# the number is a float.

        


        

          UPDATE( )
          
Unity calls Update() automatically once every frame while the game runs. Checking the keyboard here means the object keeps responding for as long as a key is held.

        


        

          READ INPUT & MOVE
          
Input.GetAxis("Horizontal") returns a value from −1 to 1 — A / left arrow negative, D / right positive, no key near zero — and Unity eases between them so starting and stopping feel smooth. "Vertical" is the same for S / W, used here for the forward / back (Z) axis. Vector3 bundles the two into a direction: x left / right, 0f no vertical movement, z forward / back (holding W gives roughly (0, 0, 1)). Every GameObject has a Transform holding its position, rotation, and scale; lowercase transform is this object's. Translate moves it by that vector, × speed sets how fast, and × Time.deltaTime — the time since the last frame — keeps the speed identical on any machine. Translate uses the object's local axes, so forward follows the way it faces.

        


      


      


    

  


  

  

    
Attaching it to an object

    
A script does nothing on its own. It runs only once it is a component on a GameObject.

    
    
      
  1. Put a cube or a model in the scene.
    2. 
      
  2. Drag MoveObject.cs from the Project window onto that object — or select the object and use Add Component in the Inspector.
    3. 
      
  3. The Speed field now shows in the Inspector. Adjust it there, even while the game is running, to feel the difference.
    4. 
      
  4. Press Play and use the arrow keys or WASD.
    5. 
    

  


  

  

    
Adding physics

    
On its own, Translate slides the object straight through walls and floors and ignores gravity. To make it collide and fall, add a physics body and colliders.


    

    

      

        
The object also needs

        

          
Rigidbody
with Use Gravity on — makes the object fall and respond to collisions.

          
Collider
on the object, and one on anything it should be able to stand on.

          
Constraints
on the Rigidbody, freeze Rotation X and Rotation Z so the object does not tip over.

          
Terrain Collider
if the ground is Unity terrain rather than a mesh.

        

      

    


    
Translate moves along the object's own axes by default, so "forward" follows the direction the object is facing.

  


  

  

    
Second script

    
A shorter way to write the same movement, for an object that already has a Rigidbody. It skips the named Vector3 and passes the axis values straight into Translate, with 0 for the vertical value. Name this file Move.cs.


    


      

        

          
          
          
          
          
        

        


using UnityEngine;

public class Move : MonoBehaviour
{
    public float speed = 5f;

    void Update()
    {
        float x = Input.GetAxis("Horizontal");
        float z = Input.GetAxis("Vertical");

        transform.Translate(x * speed * Time.deltaTime, 0, z * speed * Time.deltaTime);
    }
}

        

      


      


        

          IMPORT
          
Same as the first script — gives the script access to Unity's features.

        


        

          THE CLASS
          
Same shape as MoveObject. This one is named Move, so its file must be Move.cs. : MonoBehaviour lets it attach to a GameObject.

        


        

          INSPECTOR FIELD
          
public makes speed editable in the Inspector. float allows decimals. = 5f starts it at 5.

        


        

          UPDATE( )
          
Runs once per frame, so keyboard input is read continuously.

        


        

          READ INPUT & MOVE
          
GetAxis("Horizontal") reads A / D (eased between −1 and 1); "Vertical" reads S / W. This version skips the named Vector3 and passes the three values straight into Translate: x * speed * Time.deltaTime for left / right, 0 for vertical — the Rigidbody's gravity handles that — and z * speed * Time.deltaTime for forward / back. Time.deltaTime keeps the speed frame-rate independent, and Translate moves along the object's local axes, so a rotated object's forward rotates with it.
