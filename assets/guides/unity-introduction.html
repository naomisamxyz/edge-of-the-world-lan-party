Game Objects

    
Everything placed in a Unity scene is a GameObject: cameras, lights, characters, props, and empty organizational objects. A GameObject becomes useful through the components attached to it.

    

      

        

          
Transform
Every GameObject has one. It stores the object's position, rotation, and scale.

          
Components
Add behavior and capabilities, such as rendering, collision, audio, physics, or scripts.

          
Hierarchy
Lists the GameObjects in the current scene and shows parent-child relationships between them.

          
Inspector
Displays and edits the selected GameObject and all of its components.

        

      

    

    
Create primitive GameObjects from GameObject → 3D Object. Select an object and use the move, rotate, and scale tools to change its Transform in the Scene view.

  


  

  

    
Terrain

    
A Terrain is a specialized GameObject for building large outdoor environments. Create one with GameObject → 3D Object → Terrain, then use its Inspector tools to shape and surface the landscape.

    
For the first movement test, leave the Terrain mostly flat. Detailed shaping comes after the Rigidbody movement is working.

  


  

  

    
Physics

    
Unity's physics system controls gravity and collisions. An object needs a Rigidbody to be physically simulated and a Collider to define the shape that can make contact with other objects.

    

      

        

          
Rigidbody
With Use Gravity enabled, makes an object fall and respond to collisions.

          
Collider
Defines the object's collision shape. Anything it should hit or stand on also needs a Collider.

          
Constraints
Freeze Rigidbody rotation on X and Z when an upright object should not tip over.

          
Terrain Collider
Allows Rigidbody objects to collide with and stand on Unity Terrain.

        

      

    

  


  

  

    
Interactivity

    
Interactivity connects player input to changes in the scene. A script can continuously read a keyboard or controller, then use those values to move, rotate, or otherwise affect a GameObject.

    
Scripts are components: they only affect the scene after they are attached to a GameObject. Unity calls certain methods automatically. Update() runs once per frame, making it useful for reading continuous player input. Public variables appear in the Inspector so values such as movement speed can be adjusted without rewriting the script.

  


  

  

    
Adding interactivity

    
Create a script, add the movement code, attach it to a GameObject, and test the result.


    
Create the script

    
    
      
  1. In the Project window, create an Assets/Scripts folder. Keep scripts here instead of loose among scenes, models, and materials.
    2. 
      
  2. Open the folder, right-click inside it, and choose Create → C# Script.
    3. 
      
  3. Name the script MoveObject. The filename and class name must match exactly, so MoveObject.cs must contain public class MoveObject.
    4. 
      
  4. Double-click the script to open it in your code editor. Replace its contents with the code below and save the file.
    5. 
      
  5. Return to Unity and wait for it to compile. Check the Console before continuing: a red compiler error anywhere in the project can prevent scripts from running.
    6. 
    


    
Add movement code

    
This script reads the keyboard every frame and moves the GameObject it is attached to.


    


      

        

          
          
          
          
          
        

        


using UnityEngine;

public class MoveObject : MonoBehaviour
{
    public float speed = 3f;

    void Update()
    {
        float x = Input.GetAxis("Horizontal");

        float z = Input.GetAxis("Vertical");

        Vector3 movement = new Vector3(x, 0f, z);

        transform.Translate(movement * speed * Time.deltaTime);
    }
}

        

      


      


        

          IMPORT
          
Gives the script access to Unity's features — types such as MonoBehaviour, Vector3, Transform, Input, and Time. Almost every script starts with this line.

        


        

          THE CLASS
          
A class groups related data and instructions together. Everything from public class to the final } is its body. The name we chose is MoveObject, so the file must be named MoveObject.cs. : MonoBehaviour is what lets the class work as a Unity component — attached to a GameObject and able to use methods like Update().

        


        

          INSPECTOR FIELD
          
A variable is a named place to store a value. public makes it show up as an editable slot in the Inspector, so you can change it without editing code. float is a number that can have decimals. speed is the name. = 3f gives it a starting value of 3 — the f tells C# the number is a float.

        


        

          UPDATE( )
          
Unity calls Update() automatically once every frame while the game runs. Checking the keyboard here means the object keeps responding for as long as a key is held.

        


        

          READ INPUT & MOVE
          
Input.GetAxis("Horizontal") returns a value from −1 to 1 — A / left arrow negative, D / right positive, no key near zero — and Unity eases between them so starting and stopping feel smooth. "Vertical" is the same for S / W, used here for the forward / back (Z) axis. Vector3 bundles the two into a direction: x left / right, 0f no vertical movement, z forward / back (holding W gives roughly (0, 0, 1)). Every GameObject has a Transform holding its position, rotation, and scale; lowercase transform is this object's. Translate moves it by that vector, × speed sets how fast, and × Time.deltaTime — the time since the last frame — keeps the speed identical on any machine. Translate uses the object's local axes, so forward follows the way it faces.

        


      


      


    

    
Attach and test the script

    
A script does nothing on its own. It runs only once it is a component on a GameObject.

    
    
      
  1. Put a cube or a model in the scene.
    2. 
      
  2. Drag MoveObject.cs from the Project window onto that object — or select the object and use Add Component in the Inspector.
    3. 
      
  3. The Speed field now shows in the Inspector. Adjust it there, even while the game is running, to feel the difference.
    4. 
      
  4. Press Play and use the arrow keys or WASD.
    5. 
      
  5. Remember that Inspector changes made during Play Mode normally return to their previous values when Play Mode ends.
    6. 
    

  


  

  

    
Movement with gravity

    
The first script demonstrates general movement by changing the Transform directly. This version is for an object that should fall with gravity, collide with the ground, and travel across Terrain. It moves through a Rigidbody and keeps the Rigidbody's vertical velocity. Name the file Move.cs.


    


      

        

          
          
          
          
          
          
        

        


using UnityEngine;

[RequireComponent(typeof(Rigidbody))]
public class Move : MonoBehaviour
{
    public float speed = 5f;
    private Rigidbody body;
    private Vector3 movementInput;

    void Awake()
    {
        body = GetComponent<Rigidbody>();
    }

    void Update()
    {
        float x = Input.GetAxis("Horizontal");
        float z = Input.GetAxis("Vertical");

        movementInput = new Vector3(x, 0f, z);
    }

    void FixedUpdate()
    {
        body.velocity = new Vector3(movementInput.x * speed, body.velocity.y, movementInput.z * speed);
    }
}

        

      


      


        

          IMPORT
          
Same as the first script — gives the script access to Unity's features.

        


        

          THE CLASS
          
RequireComponent makes sure the GameObject has a Rigidbody. The class is named Move, so its file must be Move.cs.

        


        

          FIELDS
          
speed remains editable in the Inspector. body stores the attached Rigidbody, while movementInput stores the direction read from the keyboard.

        


        

          GET RIGIDBODY
          
Awake() runs when the object is initialized. GetComponent<Rigidbody>() finds the Rigidbody on the same GameObject and stores it in body.

        


        

          READ INPUT
          
Update() reads the keyboard every rendered frame and stores the X/Z direction in movementInput. Separating input from physics keeps controls responsive.

        


        

          PHYSICS MOVEMENT
          
FixedUpdate() runs in step with Unity's physics simulation. It applies the stored input as horizontal X/Z velocity. Reusing body.velocity.y preserves falling and gravity instead of forcing the vertical speed to zero.

        


      


      


    


    
Set up the object and Terrain

    
    
      
  1. Add Move.cs to the player object. Unity adds a Rigidbody automatically because the script requires one.
    2. 
      
  2. Make sure the player has an appropriate Collider.
    3. 
      
  3. Keep Use Gravity enabled on the Rigidbody.
    4. 
      
  4. Make sure the Terrain has its Terrain Collider enabled.
    5. 
      
  5. Place the player slightly above the Terrain, press Play, and use WASD or the arrow keys. Gravity brings the player down to the surface while the script supplies horizontal movement.
    6. 
    

  


  

  

    
Refining Terrain movement

    
Try the Rigidbody movement before adding constraints. The player may tip or roll when it collides with the Terrain. After observing that behavior, stabilize the player and begin shaping the environment.


    
Freeze unwanted rotation

    
    
      
  1. Select the player and open its Rigidbody component in the Inspector.
    2. 
      
  2. Expand Constraints.
    3. 
      
  3. Enable Freeze Rotation X and Freeze Rotation Z so the player remains upright. Leave Y unfrozen if the player should still be able to turn.
    4. 
      
  4. Press Play again and compare the constrained movement with the earlier test.
    5. 
    


    
Shape the Terrain

    
    
      
  1. Select the Terrain and choose Paint Terrain in the Inspector.
    2. 
      
  2. Use Raise or Lower Terrain to sculpt gentle hills, valleys, ramps, and paths.
    3. 
      
  3. Test the player frequently while shaping. Begin with gradual slopes before trying steep surfaces.
    4. 
      
  4. Use Paint Texture to create Terrain Layers and apply ground materials.
    5. 
      
  5. Add trees and details only after establishing the main scale, routes, and playable shape of the environment.
    6. 
      
  6. Keep the Terrain Collider enabled so the Rigidbody continues to collide with the finished landscape.
    7.
