Publish to GitHub

No terminal required

Before you start

  • VS Code — installed, with your project open as a folder.
  • A free GitHub.com account — sign up at github.com if you don't have one yet.
  • A finished-enough project — any folder of files works. It doesn't need to be complete.
  1. 01

    Open the Source Control panel

    Click the branching icon in the left sidebar, or press Cmd/Ctrl + Shift + G.

    >This opens the panel for Git, a program built into VS Code that keeps a history of every change you make to your project. Opening the panel doesn't change anything yet — it's just where Git's controls live.

  2. 02

    Initialize the repository

    If you see a button labeled Initialize Repository, click it.

    >Right now your folder is just files — Git isn't watching it yet. That's what "not tracked" means. Initializing tells Git to start recording this specific folder from this point on. It quietly creates a hidden .git folder inside your project, where it will store every saved version of your work from now on. You only do this once per project.

  3. 03

    Add a .gitignore

    Create a new file at the top level of your project named exactly .gitignore, and put this line in it: .DS_Store

    >Not every file on your computer belongs in your project's history. macOS quietly drops an invisible housekeeping file called .DS_Store into folders you open in Finder — it's meaningless clutter, not part of your actual project.

    >A .gitignore is a list of files and patterns you're telling Git to never track, no matter what. Once it exists, those files stop showing up as "changes" entirely — you won't accidentally stage or commit them. This step is optional on other operating systems, but harmless either way, and worth doing once per project before your first commit.

  4. 04

    Stage your changes

    Hover over "Changes" and click the + to stage everything at once, or stage individual files one at a time.

    >Git noticed your files, but it won't save anything without you telling it to. Staging is that choice — think of it like putting items in a cart before checkout. Nothing is permanently saved yet; staging just marks what should be included the next time you save.

  5. 05

    Commit

    Type a message in the box at the top, then click ✓ Commit.

    >A commit is the actual save point — a permanent snapshot of everything you just staged, added to your project's history. The message is a short note describing what's in that snapshot, for your own future reference.

    >For your very first commit, there's nothing to describe yet beyond "this is where I started" — something like "Initial commit" or "First version" is completely normal. Later on, describe what changed: "Fix header spacing," "Add contact page."

  6. 06

    Publish

    Click Publish Branch.

    >Everything so far has stayed on your own computer — GitHub doesn't know this project exists yet. Publishing does two things at once: it creates a new project on GitHub.com under your account, and it uploads your commit and its whole history there.

    >VS Code will open a browser tab to sign in, the first time only, then ask whether the project should be Public (anyone can view the files) or Private (just you, unless you invite others). If you plan to host this as a free website with GitHub Pages, it needs to be Public.

  7. 07

    Every time after

    Stage → write a commit message → click Sync Changes.

    >That's the whole loop from here on. Each round is one more snapshot added to the history, sent up to GitHub. Sync Changes is the same idea as Publish, just for a project that's already connected.

Make it a live website

GitHub can turn any public repository into a real website with its own URL, for free, using a feature called GitHub Pages. This part happens on github.com in a browser, and only needs doing once per project.
