Before building

    
A build turns the Unity project into something other people can run without opening the Unity Editor. Unity can build the same project for different platforms, but each platform creates a different set of files.

    
Install the platform modules

    
Install the required platform modules through Unity Hub:

    
    
      
  1. Open Installs.
    2. 
      
  2. Find the installed Unity 2022 version.
    3. 
      
  3. Select the gear icon.
    4. 
      
  4. Select Add modules.
    5. 
      
  5. Install the required support:
        
    Windows Build Support
Mac Build Support
WebGL Build Support
    6. 
    

    
Set up Build Settings

    
In Unity, open:

    
File → Build Settings

    
Add every required scene with Add Open Scenes. Place the first scene—usually MainMenu—at the top:

    
0  MainMenu
1  Game

  


  

    
Windows build

    
    
      
  1. Open File → Build Settings.
    2. 
      
  2. Select PC, Mac & Linux Standalone.
    3. 
      
  3. Set Target Platform to Windows.
    4. 
      
  4. Select Switch Platform.
    5. 
      
  5. Select Build.
    6. 
      
  6. Create a new folder for the build.
    7. 
    

    
Unity creates an .exe file and supporting folders. Distribute the entire folder—not only the .exe.

    
A Windows build might contain:

    
MyGame.exe
MyGame_Data
UnityPlayer.dll
MonoBleedingEdge

    
Compress the complete folder as a .zip before uploading it.

  


  

    
macOS build

    
    
      
  1. Open File → Build Settings.
    2. 
      
  2. Select PC, Mac & Linux Standalone.
    3. 
      
  3. Set Target Platform to macOS.
    4. 
      
  4. Select Switch Platform.
    5. 
      
  5. Choose an architecture:
        
    Intel 64-bit
Apple Silicon
Intel 64-bit + Apple Silicon
    
        
    Use Intel 64-bit + Apple Silicon for the broadest compatibility.
    6. 
      
  6. Select Build.
    7. 
    

    
Unity creates a .app application. Compress the .app as a .zip before uploading it. Zipping helps preserve the application’s internal folder structure and permissions.

    
For public distribution outside stores, macOS applications may need to be code-signed and notarized by Apple. Test the final build on a Mac.

  


  

    
WebGL build

    
WebGL creates a version that runs inside a web browser.

    
    
      
  1. Open File → Build Settings.
    2. 
      
  2. Select WebGL.
    3. 
      
  3. Select Switch Platform.
    4. 
      
  4. Select Build And Run for a local test.
    5. 
      
  5. Select Build when ready to publish.
    6. 
    

    
Unity creates a folder containing files such as:

    
index.html
Build
TemplateData

    
Upload the complete folder to a web server or platform such as itch.io.

    
Do not test a WebGL build by double-clicking index.html. Browsers restrict locally opened game files. Use Build And Run or a local web server.

    
WebGL publishing settings

    
Open:

    
Edit → Project Settings → Player → WebGL

    
Under Publishing Settings, choose a compression format:

    
Gzip
broadly supported and quicker to build.
Brotli
smaller downloads but requires correct HTTPS server configuration.
Disabled
larger files but easier for basic hosting.

    
For a first itch.io upload, Gzip with Decompression Fallback enabled is often the simplest option.

    
Do not enable Development Build for the public version. Development builds are larger and slower.

  


  

    
Basic build optimization

    
Optimization should reduce loading time, download size and runtime cost without noticeably damaging the experience.

    
Always test performance in a build. The Unity Editor is not an accurate measurement of the final application.

    
Bake static lighting

    
Realtime lights and shadows can be expensive. Baking calculates lighting before the game runs and stores the result in lightmaps. Use baked lighting for objects and lights that do not move.

    
Simple lighting bake

    
    
      
  1. Select static environment objects.
    2. 
      
  2. Enable Static or Contribute Global Illumination.
    3. 
      
  3. Select stationary lights.
    4. 
      
  4. Set their Mode to Baked or Mixed.
    5. 
      
  5. Open:
        
    Window → Rendering → Lighting
    6. 
      
  6. Disable Auto Generate.
    7. 
      
  7. Select Generate Lighting.
    8. 
      
  8. Save the scene.
    9. 
    

    
Unity creates lighting data and lightmaps.

    
Do not bake moving players, enemies or other dynamic objects into the lightmap. Use Light Probes to light moving objects and Reflection Probes for reflective materials.

    
Reduce realtime lights

    
    
      
  • Limit the number of realtime lights.
    • 
      
  • Avoid several shadow-casting lights affecting the same object.
    • 
      
  • Disable shadows on lights that do not need them.
    • 
      
  • Reduce shadow distance and resolution when possible.
    • 
      
  • Prefer baked lighting for static environments.
    • 
    

    
Optimize textures

    
Textures are often the largest part of a build.

    
    
      
  • Use appropriate maximum texture sizes.
    • 
      
  • Avoid 4K textures when 1K is sufficient.
    • 
      
  • Enable texture compression.
    • 
      
  • Disable Read/Write unless a script needs it.
    • 
      
  • Use smaller textures for distant or minor objects.
    • 
      
  • Use platform-specific compression settings when necessary.
    • 
    

    
WebGL builds especially benefit from smaller textures.

    
Optimize models

    
    
      
  • Remove hidden geometry.
    • 
      
  • Reduce unnecessary polygons.
    • 
      
  • Use simpler collision meshes.
    • 
      
  • Enable mesh compression when appropriate.
    • 
      
  • Use LOD Groups for objects viewed at different distances.
    • 
      
  • Combine small static environment meshes when practical.
    • 
    

    
An LOD Group displays a detailed model nearby and simpler models at greater distances.

    
Bake occlusion culling

    
Occlusion culling prevents Unity from rendering objects hidden behind walls or other geometry.

    
    
      
  1. Mark appropriate environment objects as Occluder Static or Occludee Static.
    2. 
      
  2. Open:
        
    Window → Rendering → Occlusion Culling
    3. 
      
  3. Select Bake.
    4. 
      
  4. Test the result with the Visualization tab.
    5. 
    

    
Occlusion culling is most effective in interiors, cities and environments with many blocked sightlines.

    
Optimize audio

    
    
      
  • Compress music and long sound effects.
    • 
      
  • Use mono audio for sounds that do not require stereo.
    • 
      
  • Use lower sample rates when the difference is not noticeable.
    • 
      
  • Stream long music tracks instead of loading everything into memory.
    • 
      
  • Remove unused audio files.
    • 
    

    
Remove unused content

    
    
      
  • Remove unused scenes from Build Settings.
    • 
      
  • Remove unused assets from Resources folders.
    • 
      
  • Avoid including unnecessary high-resolution source files.
    • 
      
  • Disable packages and plugins the project does not use.
    • 
      
  • Check the Editor log after building to see which assets use the most space.
    • 
    

    
Use object pooling

    
Frequently creating and destroying objects can cause performance problems. Object pooling is helpful for:

    
    
      
  • Projectiles
    • 
      
  • Enemies
    • 
      
  • Particles
    • 
      
  • Collectibles
    • 
      
  • Repeated visual effects
    • 
    

    
Instead of destroying an object, deactivate and reuse it:

    
// Hide the object so it can be reused later.
gameObject.SetActive(false);

    
Profile the build

    
Use:

    
Window → Analysis → Profiler

    
Create a temporary Development Build and enable Autoconnect Profiler. Check:

    
    
      
  • CPU usage
    • 
      
  • GPU usage
    • 
      
  • Memory
    • 
      
  • Rendering
    • 
      
  • Physics
    • 
      
  • Audio
    • 
    

    
Turn Development Build off before creating the public release.

  


  

    
Distribution

    
Windows
Upload a .zip containing the complete Windows build folder.
macOS
Upload a .zip containing the .app. Code-sign and notarize it when distributing publicly outside a controlled classroom environment.
WebGL
Upload the complete WebGL build folder. For itch.io, upload a .zip with index.html at its root and mark the project as playable in the browser.

    
Possible distribution platforms include:

    
    
      
  • itch.io
    • 
      
  • A personal website
    • 
      
  • A school server
    • 
      
  • Steam
    • 
      
  • Microsoft Store
    • 
      
  • Mac App Store
    • 
    

    
Desktop builds are downloaded and run locally. WebGL builds are downloaded by the browser and should therefore remain as small as possible.

  


  

    
Final checklist

    
Before distribution:

    
    
      
  • Add every required scene to Build Settings.
    • 
      
  • Put the correct starting scene first.
    • 
      
  • Set the game name, icon and version in Player Settings.
    • 
      
  • Remove testing objects and debug messages.
    • 
      
  • Bake static lighting.
    • 
      
  • Bake occlusion culling when useful.
    • 
      
  • Compress large textures and audio.
    • 
      
  • Test every menu and scene transition.
    • 
      
  • Test the new Input System controls.
    • 
      
  • Create a non-development release build.
    • 
      
  • Test the final build outside the Unity Editor.
    • 
      
  • Test on the actual target platform.
    • 
      
  • Include the entire build—not only the executable.
