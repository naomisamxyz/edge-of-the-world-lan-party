Zip snapshots

    
If Git feels like too much right now, this is the bare-minimum alternative: whenever you've made changes and have a working version, zip your project folder to make a copy, then keep working in the copy. There's no diffing, no branching, and no partial undo — the only move is "go back to an older zip" — but it means a bad session can never cost you the last version that worked.

    

      

        
Naming the copies

        

          
Sequential
increment a number every time, such as ProjectName_01.zip, ProjectName_02.zip. Simple, and sorts correctly by name.

          
Dated
stamp the date, such as ProjectName_2026-09-19.zip. Add a letter or time if you make more than one copy a day.

          
Described
add a few words about what changed, such as ProjectName_03_player-jump-fixed.zip. Slower to write, much faster to find later.

          
Where
keep the zips outside the live project folder, in a separate backups folder, so you never accidentally zip a zip.

        

      

    

    
This is a safety net, not version control — there is no way to see what changed between two zips, merge work from two people, or recover just one file out of the whole project. Once more than one person is working on the project, or you want that finer-grained history, move to Git below.

  


  

  

    
Git and GitHub

    
Use source control from the first day. Git records history locally; GitHub adds an off-machine copy and makes collaboration possible.

    
(This guide is written for Mac. Windows notes are called out at each step — mostly it's the same GitHub Desktop app, just different installers for the Terminal-only parts.)


    
1. Install the tools

    
    
      
  1. Mac only: Install Homebrew if you don't have it (run the command it gives you, then the post-install step it prints). Windows: skip Homebrew — you'll install Git directly from git-scm.com instead (just run the installer, defaults are fine).
    2. 
      
  2. Mac, in Terminal:
        
    brew install git
    
      
    3. 
      
  3. Download and install GitHub Desktop — same app on both platforms. On Mac, unzip and drag into Applications; on Windows, run the installer.
    4. 
      
  4. Open GitHub Desktop → Settings/Options → Accounts → Sign in to GitHub.com.
    5. 
      
  5. GitHub Desktop → Settings/Options → Git → enter your name and email (same ones as your GitHub account).
    6. 
    


    
2. Prepare the Unity project

    
    
      
  1. In Unity: Edit → Project Settings → Editor
        
      
          
    • Version Control Mode → Visible Meta Files
      • 
          
    • Asset Serialization Mode → Force Text
      • 
        
    
      
    2. 
      
  2. Download the Unity .gitignore template.
        
      
          
    • Rename it from Unity.gitignore to exactly .gitignore. Mac: it'll show a plain question-mark icon afterward — that's normal, ignore it. Windows: File Explorer may block naming a file starting with a dot and no extension via the rename box — if so, rename it in a text editor's "Save As" dialog instead, or wrap the name in quotes (".gitignore") when renaming.
      • 
          
    • Move it into the project's root folder, right next to Assets, Packages, and ProjectSettings.
      • 
        
    
      
    3. 
      
  3. Open the .gitignore in a text editor and add one more line at the bottom:
        
    .DS_Store
    
        
    (This line only matters on Mac — it ignores Finder's metadata file. Harmless to leave in on Windows too.)
    
      
    4. 
    


    
3. Create the repository — GitHub Desktop only

    
    
      
  1. Close Unity.
    2. 
      
  2. GitHub Desktop → File → Add Local Repository.
    3. 
      
  3. Click Choose... and select your project folder (do not use "New Repository" — that can create an unwanted extra subfolder).
    4. 
      
  4. It'll say "This directory does not appear to be a Git repository" — click create a repository right there. In the dialog that opens, the Local Path field shows the parent folder (the one containing your project), and a separate Name field shows your project folder's name — that's expected, not an error. Just confirm the Name field matches your actual project folder name exactly, then confirm. GitHub Desktop will make an automatic initial commit for you at this point.
    5. 
      
  5. Check the History tab to see that initial commit, and the Changes tab going forward for anything new. You should not see Library, Logs, obj, UserSettings, .vs, or .DS_Store show up as tracked. If those appear, the .gitignore wasn't in the right spot before the repo was created — fix it and remove those files from tracking before continuing.
    6. 
      
  6. Click Publish repository, choose public or private, and confirm.
    7. 
    


    
4. Git LFS (only if your project has large binary assets — video, big audio, huge textures, or 3D files like .fbx/.blend/.c4d/.obj)

    
This part still needs Terminal (Mac) or Git Bash/Command Prompt (Windows) — there's no GUI for setting tracking rules. Run these one at a time, in order — each does something different, and the later ones depend on the earlier ones having finished:

    
    
      
  1. Install Git LFS itself (only needed once per computer).
        
      
          
    • Mac:
            
      brew install git-lfs
      
          
      • 
          
    • Windows: download and run the installer from git-lfs.com, or if you installed Git for Windows recently it may already be bundled — check with git lfs version.
      • 
        
    
      
    2. 
      
  2. Enable LFS for your Git installation (only needed once per computer):
        
    git lfs install
    
      
    3. 
      
  3. Move into your project folder (needed every time you open a new Terminal/Command Prompt window):
        
    cd "/Users/your-name/Unity Projects/Class Project"
    
        
    Windows: the path will look like cd "C:\Users\your-name\Unity Projects\Class Project".
    
      
    4. 
      
  4. Tell LFS which file types to track (only needed once per project, or whenever you want to add more types later):
        
    git lfs track "*.psd" "*.fbx" "*.blend" "*.c4d" "*.obj" "*.wav" "*.mp4" "*.mov" "*.zip"
    
        
    Add or remove extensions based on what your project actually uses.
    
      
    5. 
    

    
Step 4 updates a file called .gitattributes. After running it, go back to GitHub Desktop — you'll see .gitattributes listed as changed — commit it and push using the normal buttons.


    
5. Everyday workflow — GitHub Desktop only

    
After making changes in Unity:

    
    
      
  1. Open GitHub Desktop — it shows what changed.
    2. 
      
  2. Write a short summary of what you did → Commit to main.
    3. 
      
  3. Click Push origin.
    4. 
    

    
Commit after a meaningful change, and before trying something experimental. If working with others, click Fetch origin / Pull before you start working, and avoid two people editing the same scene at once.


    
Large files and recovery

    
Don't commit generated folders (Library, Temp, Obj, Logs) or exported builds — they're regenerated automatically and the .gitignore already keeps them out. For large binary assets that must be versioned, use Git LFS (above).

    
To recover from a ZIP backup, extract it into a new folder and open the copy. To recover with Git, use GitHub Desktop's History tab to find the last good commit, right-click it, and revert or check out from there.
